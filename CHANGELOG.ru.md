# История изменений

[English](CHANGELOG.md)

Что изменилось в каждом выпуске podkop-exp, от новых к старым. Движок — сборка sing-box
[podkop-engine](https://github.com/podkop-net/podkop-engine), которая стоит внутри выпуска.
Полные описания, с замерами на стенде и ограничениями, — на
[странице выпусков](https://github.com/podkop-net/podkop-experimental/releases).

## 0.8.17 — 2026-11-17

Движок r27.

- **BitTorrent сделан заново.** О соединении клиента роутер решает по его первому пакету. То, чего
  по нему не понять, идёт через собственный модуль podkop в sing-box. Модуль узнаёт адреса пиров из
  ответов трекеров и DHT ещё до того, как их получит клиент, и проверяет соединения на необычные
  порты по зашифрованному рукопожатию BitTorrent. При «Мимо podkop» на стенде aria2, Transmission и
  rTorrent шли к пирам напрямую на 99,9–100 % (0.8.16: aria2 — 2,4 %, rTorrent — 0 %).
- **BitTorrent, «Блокировать»:** соединения других программ больше не обрываются по виду их
  первых данных. 0.8.16 обрывал Shadowsocks 2022, VMess, obfs4 и другие.
- **BitTorrent через правило** — и для всей локальной сети (новое поле «Чей BitTorrent идёт через
  правило»).
- **Статистика BitTorrent** на «Дашборде» и в «Глобальной проверке»: трафик по видам (DHT, uTP,
  TCP, входящие) и по путям. Считают счётчики самого роутера, podkop читает их раз в 5 с.
  `podkop bittorrent_stats` — то же в JSON.
- **Ограничения:** только IPv4. aria2 повторяет закрытое зашифрованное соединение без шифрования;
  при «Мимо podkop» провайдер видит его открытым.

## 0.8.16 — 2026-11-15

Движок r27.

- **BitTorrent:** новая настройка для BitTorrent-трафика, который взял бы podkop: «Мимо podkop»,
  «Блокировать» (только то, что берёт podkop, или всю локальную сеть) или «Через серверы правила».
  Новая зависимость — `kmod-nf-conntrack-netlink`.
- **Выбор сервера:** «Самый быстрый с учётом потерь» и «Балансировка между лучшими» считают потери
  серверов Hysteria2 и TUIC по пакетам их соединения QUIC. Раньше такие серверы выбирались только по
  задержке.
- **Исправлено:** проброс портов на устройство из «Полностью маршрутизированных IP-адресов».

## 0.8.15 — 2026-11-14

Движок r26.

- **Загрузки:** списки и подписки, которые не приходят напрямую, приходят через серверы правил.
  Сначала пробуется путь, которым файл пришёл в прошлый раз; одновременно — не больше трёх путей.
  На стенде список пришёл за 12 с; 0.8.14 не получил его и за 180 с.
- **Серверы:** источник можно исключить из загрузок («Не использовать для загрузки списков и
  подписок»).
- **Обход блокировки:** маска в собственной ссылке сервера больше не мешает применить настройки, а
  обход не идёт через сервер, который сам подключён через другой.
- **Детектор блокировок** находит лимит у Shadowsocks и тогда, когда обрыв приходится на середину
  зашифрованного блока.
- **Движок r26:** hysteria2 на роутерах без AES (MT7621) тратит на 34 % меньше процессора на
  гигабайт; DNS — меньше процессора на запрос.

## 0.8.14 — 2026-11-12

Движок r25.

- **Обход блокировки:** «Подобрать маску» пробует и имена из открытых белых списков. Их адреса — в
  «Настройках» («Адреса списков масок»).
- **Списки** скачиваются сами: напрямую, затем через серверы первых трёх правил. Настройки
  «Скачивать списки через Proxy/VPN» больше нет.
- **Дашборд:** «Тестирование задержки» показывает свой результат рядом с медианой.
- **Исправлено:** «Подключаться через <сервер>» через сервер той же подписки. Серверу без TLS маска
  больше не предлагается.
- **Движок r25:** когда один сервер DNS-группы не ответил вовремя, группа спрашивает остальные
  разом.

## 0.8.13 — 2026-11-12

Движок r24.

- **Обход блокировки для отдельного сервера.** Окно проверки предлагает обход, который подходит
  вердикту: маску сайта из белого списка при «лимите», деление ClientHello при «заморозке»,
  «Подключаться через <сервер>» при «нет пути отсюда». Обход привязан к серверу, а не к его имени,
  и хранится в `/etc/config/podkop` (секции `cure`).
- **Движок r24:** `fragment` и `record_fragment` работают и у REALITY (раньше молча не применялись).

## 0.8.12 — 2026-11-07

Движок r23 (отдельным выпуском podkop-engine не выходил; его изменения вошли в r24).

- **Восстановление:** отдельной службы-сторожа больше нет. Упавший бэкенд перезапускает procd. С
  четвёртого падения подряд роутеру возвращается его собственный DNS, а бэкенд пробуется снова
  через 1, 2, 4 … 60 минут.
- **dnsmasq:** перенаправления для отдельных доменов (для Tailscale — `/ts.net/100.100.100.100`)
  сохраняются. Глобальная проверка предупреждает, если такой домен есть и в списках podkop.
- **Подписки:** провайдер, который не отвечает, описывается одной строкой.

## 0.8.11 — 2026-11-06

Движок r23 (отдельным выпуском podkop-engine не выходил; его изменения вошли в r24).

- **Выбор сервера в правиле** (вкладка «Доп. настройки»): «Самый быстрый»; «Самый быстрый с учётом
  потерь» (потери меряются небольшими скачиваниями через серверы); «Балансировка между лучшими»
  (устройства распределяются по лучшим серверам). Потери видны на дашборде; в глобальной проверке
  есть раздел «Server choice».
- **Подписки:** «Обновить сейчас». Интервал обновления, который просит провайдер, действует сразу.
- **Имена:** журнал, YACD и глобальная проверка называют серверы и правила их именами, а не
  src1/src2.

## 0.8.10 — 2026-11-04

Движок r22 (отдельным выпуском podkop-engine не выходил; его изменения вошли в r24).

- **DNS после перезагрузки:** dnsmasq с самого старта спрашивает podkop. Если dnsmasq работает не с
  теми настройками, что для него записаны, его перезапускают.
- **Проверка серверов:** пять адресов по умолчанию по очереди, круг в минуту. Задержка — медиана за
  полный круг, так что одна случайная проверка не переключает сервер. Трафика проверок стало
  примерно втрое больше (около 24 МБ в сутки на работающий сервер).
- **Вкладка «Серверы»:** порядок источников меняется перетаскиванием. Окно подписки умеет
  копировать ссылки её серверов.

## 0.8.9 — 2026-11-03

Движок r21.

- **Детектор блокировок:** у неработающего сервера метка с причиной («нет ответа», «заморозка»,
  «лимит», «нет пути», «отказ» …). «Проверить» называет вид блокировки. Детектор только показывает:
  маршруты он не меняет.
- **Дашборд:** серверы правила разложены по ярусам (самый быстрый, запасной 1, запасной 2 …).
  «Вернуть автовыбор» снимает закрепление.
- **DNS:** несколько серверов (DoH, DoT, UDP, DNS провайдера) — по порядку или сначала самый
  быстрый. Замолчавший сервер откладывается.
- **Диагностика:** проверяется только сервер, через который правило идёт сейчас (на стенде 0,3 с
  вместо 12 с).
- **Исправлено:** ссылки XHTTP с JSON в `extra`; ws и httpupgrade висели на молчащем сервере.

## 0.8.8 — 2026-10-30

Движок r20.

- **Серверы отдельно от правил.** Во вкладке «Серверы» — источники: подписки, ссылки, Outbound
  JSON, интерфейсы. Во вкладке «Правила» правило берёт серверы из источников, по словам в их именах,
  при желании — «Через» другой источник. Групп больше нет.
- **Запасные:** строки по порядку (другой источник, «Напрямую», «Блокировать») — на случай, когда не
  отвечает ни один сервер правила.
- **Проверка серверов** одна на все правила, на роутере одновременно не больше 4 проверок.
- **Переход:** настройки podkop 0.7 и podkop-exp до 0.8.7 переводятся сами. Прежний файл остаётся
  как `/etc/config/podkop.pre-0.8.8`.

## 0.8.7 — 2026-10-29

Движок r19.

- **Подписки без обрыва соединений:** изменение подписки больше не перезапускает sing-box.
  Заменённый сервер закрывается, когда на нём не осталось соединений, но не позже чем через сутки.
- **Загрузка подписок:** к медленному пути рядом добавляется второй. «Загрузить» ждёт до минуты и
  показывает каждый путь. Ошибки понятны. Видны трафик, срок и сообщения провайдера.
- **Исправлено:** список-заглушка (все серверы 0.0.0.0) больше не заменяет рабочий.

## 0.8.6 — 2026-10-28

Движок r18.

- **Исправлено** в подписках и группах из 0.8.5: страница не открывалась на OpenWrt 25.12 с группой
  без подписки; на чистой установке не добавлялись записи; подписка, добавленная после
  «Загрузить», скачивается заново через 10 с (раньше ждала до 12 часов). Удаление пакета удаляет и списки подписок.

## 0.8.5 — 2026-10-27

Движок r18.

- **Подписки и группы.** Роутер сам скачивает подписку — напрямую или через свои серверы.
  Идентификатор устройства (HWID) берётся из железа роутера. Список хранится на роутере, так что
  правила работают и при старте без сети.
- **Списки:** их содержимое лежит в файлах рядом с cache.db. Большие списки обновляются по одному.
- **Часы:** если время на роутере неверное, podkop помогает NTP и сверяет время по HTTPS.
- **Глобальная проверка** предлагает MTU для VPN-секции, проверка которой не проходит.

## 0.8.4 — 2026-10-25

Движок r17.

- **Автосмена отпечатка uTLS включена по умолчанию:** сначала пробуется отпечаток без
  X25519MLKEM768, затем firefox, затем отпечаток как есть. Выбор запоминается для сервера на сутки.
- **Открываются сайты только с IPv6:** адрес IPv6 отдаётся, если у имени нет адреса IPv4.
- **Исправлено:** с Tailscale соединения устройств сети через прокси больше не зависают.

## 0.8.3 — 2026-10-24

Движок r16.

- **Подключаться через:** секция может подключаться через другую (прокси через прокси, группу или
  VPN).
- **mwan3:** резервный DNS спрашивает провайдера каждого аплинка. Соединения, привязанные к WAN,
  работают. Неудачный старт повторяется.
- **YACD** входит в пакет; обновляется кнопкой в самом YACD.
- **Память:** миллион подсетей и 500 тысяч доменов занимают 151 МБ вместо 251 МБ.
- **Установщик** скачивает пакеты через API GitHub (wget в OpenWrt зависал на ссылках github.com).
- 0.8.2 продержался около часа: форма ошибочно сообщала о петле при выборе VPN-секции в
  «Подключаться через». В 0.8.3 это исправлено.

## 0.8.1 — 2026-10-23

Движок r15.

- **Страница:** команды отвечает работающий бэкенд, поэтому страница почти не нагружает роутер.
- **Ссылки прокси** проверяются до сохранения.
- **sing-box не привязан к интерфейсу:** работают mwan3 и маршруты к отдельным хостам.
- **Поля интерфейсов** принимают сеть (wan, lan, guest) или порт PPPoE.
- **YACD** открывается только с выбранных устройств.

## 0.8.0 — 2026-10-20

Движок r15.

- Первый выпуск: podkop 0.7.24 с бэкендом на Go и sing-box (podkop-engine) внутри. Работает с
  настройками и страницей LuCI podkop.
