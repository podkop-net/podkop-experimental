## Первый запуск

1. Вкладка **«Серверы»**: вставьте адрес подписки или ссылку на сервер в пустой источник `src1`.
   Тип источника определяется по тексту.
2. Нажмите **«Сохранить и применить»**. Правило `main` (списки сообщества Russia inside, Discord и
   Telegram) уже берёт серверы из `src1`.
3. Откройте **«Дашборд»**. Плитка сервера, через который идёт правило, выделена.

Пока ни один источник не заполнен, podkop ничего на роутере не меняет.

## Серверы

Источник — это одно из:

- **подписка** — адрес провайдера. **«Загрузить»** показывает её серверы ещё до сохранения. После
  «Сохранить и применить» роутер сам скачивает список и хранит его, так что правила работают и при
  старте без сети. В окне подписки — её состояние, трафик и срок от провайдера, кнопка
  **«Обновить сейчас»** и кнопки для копирования ссылок;
- одна или несколько **ссылок на серверы** (`vless://`, `ss://`, `trojan://`, `hy2://` …; см.
  [примеры](../String-example.md));
- **Outbound JSON** для sing-box;
- **интерфейс** — туннель, настроенный на роутере (WireGuard, AmneziaWG …), модем или второй WAN.

Порядок источников (перетаскивание ☰) меняет только вид. Отметка **«Не использовать для загрузки
списков и подписок»** исключает источник из загрузок. Она нужна, например, для подписки с малым
трафиком или туннеля в закрытую сеть.

## Правила

Правило говорит, какие сайты через какие серверы идут. Если сайт есть в нескольких правилах,
действует верхнее; порядок меняется перетаскиванием ☰. У правила четыре вкладки:

- **«Основное»** — списки правила. Это могут быть списки сообщества, свои домены и подсети
  (**«Динамический список»** или **«Текстовый список»**), списки по ссылке и **«Полностью маршрутизированные IP-адреса»** —
  устройства, весь трафик которых идёт по этому правилу.
- **«Серверы»** — одна или несколько строк. Строка — это источник и, по желанию, фильтры.
  **«Имя содержит»** и **«Имя не содержит»** ищут начало слова: `NL` найдёт `NL-1` и
  `Amsterdam NL`, но не `RU2NL`. Столбец **«Через»** подключает к серверам строки через другой
  источник. Строкой может быть также **«Напрямую»** (исключение) или **«Блокировать»**.
- **«Запасные»** — строки по порядку. Они берутся, когда не отвечает ни один сервер правила. Если
  запасной — «Блокировать», правило возвращается на свои серверы вскоре после того, как сеть
  вернулась.
- **«Доп. настройки»** — выбор сервера и локальный смешанный прокси правила.

Выбор сервера:

| Режим | Как выбирается сервер | Цена |
|---|---|---|
| Самый быстрый | наименьшая медиана задержки по проверкам серверов; переключение — только на сервер, который быстрее на допуск (в «Настройках») | только проверки |
| Самый быстрый с учётом потерь | задержка с учётом потерь, которые насчитывают скачивания по 256 КБ через текущий сервер и три следующих лучших | около 50 МБ в сутки на правило при 30 минутах по умолчанию |
| Балансировка между лучшими | устройства распределяются между лучшими серверами и остаются на своём; сервер с большими потерями устройств не получает | около 60 МБ в сутки на правило (проверяются пять серверов) |

## Настройки

Вкладка — один список; здесь поля сгруппированы по смыслу.

| Поля | Что задают |
|---|---|
| DNS-серверы | строки DoH, DoT, UDP или **«DNS провайдера»**, которые спрашиваются **«По порядку»** или **«Сначала самый быстрый»**; bootstrap DNS-сервер; TTL в ответах podkop |
| Проверка серверов | адреса, интервал и допуск проверок задержки для всех правил; проверка загрузки |
| uTLS-fallback | включено по умолчанию: сначала пробуется отпечаток ссылки без ключа X25519MLKEM768, затем firefox, затем отпечаток как есть; первый прошедший запоминается для сервера и раз в сутки проверяется заново |
| BitTorrent | **«Как остальной трафик»**, **«Мимо podkop»**, **«Блокировать»** или **«Через серверы правила»**; два последних — для того, что берёт podkop, или для всей сети |
| Открытые списки масок | откуда «Подобрать маску» берёт имена сайтов из белых списков |
| Интерфейсы | интерфейс локальной сети, который обслуживает podkop, и выходной интерфейс для его собственных соединений |
| YACD | панель YACD: включена или нет, с каких интерфейсов открывается, её ключ |
| Прочее | «Отключить QUIC», частота обновления списков, «Dont Touch My DHCP!», файл кэша, уровень журнала, «Исключить NTP», IP-адреса, исключённые из маршрутизации |

## Дашборд

- Плитка сервера, через который идёт правило, выделена. Если серверов несколько, строка под
  именем правила ещё и говорит, как он выбран: автовыбор, запасной или **«Вручную»**. Серверы
  показаны плитками, по ярусам: самый быстрый, затем запасной 1,
  запасной 2 …
- На плитке — задержка. В режимах с потерями ещё и потери (`~`, пока проверок мало) и число
  устройств в балансировке (`⇄N`).
- Нажатие на плитку закрепляет этот сервер. **«Вернуть автовыбор»** снимает закрепление.
  **«Тестирование задержки»** проверяет серверы сейчас и показывает результат рядом с медианой.
- У неработающего сервера появляется метка с причиной: нет ответа, заморозка, лимит, нет пути,
  отказ и другие. **«Проверить»** (или **«Проверить проблемные»**) проверяет сервер и называет вид
  блокировки. Окно может предложить **«Обход блокировки для этого сервера»**:

  | Вердикт | Обход |
  |---|---|
  | лимит (соединения обрываются около 16–20 КБ) | маска: сначала уходит поддельное TLS-приветствие сайта из белого списка. **«Подобрать маску»** ищет имя, которое работает на этом сервере |
  | заморозка | TLS-приветствие разбивается на две записи, или автосмена отпечатка uTLS |
  | нет пути | подключение через тот сервер, через который проверка до него достучалась |

  Обход принадлежит серверу и переживает переименование. Пометка на плитке открывает окно, где
  обход можно убрать.
- Карточка **BitTorrent** (если BitTorrent не «Как остальной трафик») показывает трафик
  BitTorrent-клиентов: по видам (DHT и UDP-трекеры, uTP, TCP, входящие) и по путям.

## Диагностика

- **«Запустить диагностику»** проверяет DNS, sing-box, правила файрвола, FakeIP и серверы, через
  которые правила идут сейчас.
- **«Получить глобальную проверку»** собирает всё в один отчёт, ключи и пароли в нём скрыты. Этот
  отчёт и нужно прикладывать к issue.
- **«Посмотреть логи»** и **«Показать sing-box конфигурацию»** показывают журнал и работающую
  конфигурацию.
- Перезапуск, остановка, запуск, автозапуск — вкл. и выкл.

## Если что-то не работает

1. «Диагностика» → **«Запустить диагностику»**. Строка с ошибкой говорит, что не так.
2. **«Получить глобальную проверку»**. Она смотрит ещё часы роутера, работает ли dnsmasq с
   записанными для него настройками, выбор сервера и BitTorrent.
3. Сервер помечен на дашборде: **«Проверить»**, затем предложенный обход.
4. Не приходит подписка: её окно показывает, какие пути пробовались и почему каждый не сработал.
   Для списков `podkop list_status` показывает последнюю ошибку каждого.
5. Всё ещё не работает: откройте [issue](https://github.com/podkop-net/podkop-experimental/issues)
   с глобальной проверкой и описанием того, что вы делали. Журнал — `logread -e podkop`.

## Командная строка

| Команда | Что делает |
|---|---|
| `podkop global_check` | глобальная проверка |
| `podkop check_logs` | журнал бэкенда и sing-box |
| `podkop show_config`, `podkop show_sing_box_config` | настройки и работающая конфигурация sing-box, секреты скрыты |
| `podkop reload` | применить настройки заново и сказать, чем кончилось |
| `podkop list_update` | скачать все списки сейчас |
| `podkop subscription_update [имя]` | скачать подписку (или все) сейчас |
| `podkop bittorrent_stats` | статистика BitTorrent в JSON |
| `service podkop restart` | перезапустить службу |

`podkop` без аргументов перечисляет все команды.
