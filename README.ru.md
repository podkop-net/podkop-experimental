# podkop-exp

[English](README.md)

Репозиторий для тестов новой функциональности [podkop](https://github.com/itdoginfo/podkop). То,
что проверяется здесь, может потом войти в podkop, измениться или исчезнуть.

podkop-exp ставится вместо podkop и сохраняет его файл настроек (`/etc/config/podkop`) и страницу в
LuCI. Бэкенд — одна программа на Go с sing-box внутри, отдельный пакет sing-box не нужен.

## Что добавляет к podkop

- **Один бэкенд с движком внутри.** Страница спрашивает работающий бэкенд, поэтому почти не
  нагружает роутер. Если бэкенд падает раз за разом, роутеру возвращается его собственный DNS.
- **Движок — [podkop-engine](https://github.com/podkop-net/podkop-engine)**, сборка sing-box.
  Работает с современными серверами Xray (REALITY с X25519MLKEM768), умеет транспорт XHTTP и
  шифрование VLESS.
- **Серверы отдельно от правил.** Подписки, ссылки, Outbound JSON и интерфейсы — на вкладке
  «Серверы». Правило берёт из них серверы по словам в именах и может подключаться через другой
  источник.
- **Подписки скачивает сам роутер.** Идентификатор устройства (HWID) берётся из железа. Видны трафик
  и срок подписки. Изменение списка не перезапускает sing-box, так что открытые соединения
  остаются. У провайдера, который отдаёт список только некоторым приложениям, его можно запросить
  с названием такого приложения (User-Agent) и дополнительными заголовками; HWID остаётся
  собственным HWID роутера.
- **Автовыбор сервера в каждом правиле:** самый быстрый, самый быстрый с учётом потерь или
  балансировка между лучшими. Запасные («Напрямую», «Блокировать», другие серверы) включаются,
  когда не отвечает ни один сервер. Сервер можно закрепить на дашборде.
- **Правила для части устройств:** правило может брать трафик только выбранных устройств (адреса
  и подсети IPv4 или IPv6) — например, YouTube через серверы только на телевизоре, а на остальных
  он заблокирован ([руководство](docs/GUIDE.ru.md#правило-для-части-устройств)).
- **Детектор блокировок и обход.** У неработающего сервера видна причина (нет ответа, заморозка,
  лимит, нет пути …). «Проверить» проверяет сервер и может предложить обход: маску сайта из белого
  списка, разбиение ClientHello на две записи или подключение через другой сервер.
- **Автосмена отпечатка uTLS, включена по умолчанию.** Сначала пробуется отпечаток TLS из ссылки
  без ключа X25519MLKEM768, на котором ТСПУ замораживает соединения, затем firefox, затем отпечаток
  как есть. Первый прошедший запоминается для сервера.
- **Загрузки, которые доходят.** Списки и подписки, которые не приходят напрямую, приходят через
  серверы ваших правил. Сначала пробуется путь, который сработал в прошлый раз.
- **DNS:** несколько серверов (DoH, DoT, UDP, DNS провайдера; IPv4 или IPv6) — по порядку или
  сначала самый быстрый; в ответах сначала IPv4, только IPv4 или оба. DNS провайдера — запасной, на каждом аплинке. После перезагрузки dnsmasq
  по-прежнему отправляет запросы podkop. Перенаправления отдельных доменов (Tailscale) сохраняются.
- **BitTorrent:** настройка отправляет его мимо podkop, блокирует или отправляет через серверы
  правила — для того, что берёт podkop, или для всей сети, и для клиента на самом роутере. Его
  статистика — на дашборде. Чего он не умеет — в [руководстве](docs/GUIDE.ru.md#bittorrent).
- **Дашборд и диагностика:** маршрут каждого правила, серверы с задержкой и потерями, трафик
  BitTorrent. Глобальная проверка смотрит ещё часы роутера, состояние dnsmasq, выбор сервера и
  подсказывает MTU для VPN-интерфейсов.
- **IPv6:** мимо podkop или через него — для подсетей IPv6 из списков, как IPv4
  ([руководство](docs/GUIDE.ru.md#ipv6)).
- **Несколько аплинков:** работают mwan3 (балансировка и резерв), PPPoE, маршруты к отдельным хостам
  и Tailscale.
- **YACD в пакете**, открывается только с выбранных устройств.
- **Настройки podkop переводятся** при установке, прежний файл остаётся, чтобы можно было вернуться.

## Установка

OpenWrt 24.10 или новее, не меньше 80 МБ оперативной памяти. В консоли роутера (SSH):

```sh
sh <(wget -O - https://raw.githubusercontent.com/podkop-net/podkop-experimental/main/install.sh)
```

Если консоль не принимает эту строку, сначала скачайте установщик:

```sh
wget -O /tmp/install.sh https://raw.githubusercontent.com/podkop-net/podkop-experimental/main/install.sh && sh /tmp/install.sh
```

Установщик проверяет роутер и показывает, что сделает: выпуск, версию, которая стоит сейчас, и
установленные пакеты, рядом с которыми podkop-exp не работает (podkop и его страница,
podkop-engine; https-dns-proxy, nextdns или luci-app-xray — они забирают себе пересылку DNS у
dnsmasq). Он один раз спрашивает, удалить ли их и ставить ли русский перевод, и только потом
что-то меняет: если ответить «нет», на роутере ничего не меняется. Настройки podkop сохраняются:
podkop-exp переводит их в свой формат, а в прежнем формате оставляет как
`/etc/config/podkop.pre-0.8.8` (если такой файл остался от прошлой установки, установщик сначала
копирует текущий файл под именем с датой и называет его). Если места на флеше не хватает, он затем
предлагает удалить пакеты sing-box, которые ничему не нужны (sing-box уже внутри podkop-exp). Он
показывает вывод каждой команды по ходу дела, а при ошибке говорит, что уже сделано.

Параметры — в конце команды:

| | |
|---|---|
| `-y` | «да» на вопросы, для скриптов: удалить пакеты, рядом с которыми podkop-exp не работает, и ненужные пакеты sing-box, поставить более старый выпуск из `--release`. Перевод остаётся как был: стоял — останется |
| `--ru`, `--no-ru` | поставить русский перевод страницы без вопроса или не ставить его |
| `--release 0.8.19` | этот выпуск вместо последнего, в том числе более старый (0.8.8 или новее). Старый выпуск не отменяет перевода настроек в новый формат и не знает параметров, добавленных после него |
| `--from DIR` | файлы пакетов из `DIR` вместо загрузки ([ниже](#установка-без-api-github)) |

Без терминала (в скрипте) ответы читаются со входа: `echo y | sh /tmp/install.sh`.

Обновление — та же команда; после неё очистите кэш браузера для страницы LuCI (или откройте её в
приватном окне). Если этот выпуск уже стоит, установщик так и скажет и ничего не изменит.

Если podkop запущен и загрузка не проходит, остановите его (`service podkop stop`) и запустите
команду снова. Установщик подскажет это, если адрес GitHub приходит из диапазона FakeIP podkop.

### Установка без API GitHub

API GitHub принимает 60 запросов в час с одного адреса, а абоненты мобильного оператора часто
выходят с одного адреса. Если установщик пишет «GitHub refused the request»:

1. На компьютере скачайте со [страницы выпуска](https://github.com/podkop-net/podkop-experimental/releases):
   - `podkop-exp-<версия>-<архитектура>.ipk` (`.apk` на OpenWrt 25.12). Архитектура роутера, через
     дефисы: `. /etc/openwrt_release; echo $DISTRIB_ARCH | tr _ -`. Например,
     `podkop-exp-v0.8.20-r1-aarch64-cortex-a53.ipk`;
   - `luci-app-podkop-exp-<версия>-all.ipk` (`luci-app-podkop-exp-<версия>.apk`);
   - для русского языка — `luci-i18n-podkop-exp-ru-<версия>.ipk` (`.apk`).
2. Скопируйте их на роутер. `-O` нужен потому, что SSH-сервер OpenWrt (dropbear) не умеет SFTP, а
   `scp` по умолчанию использует его.

   ```sh
   ssh root@192.168.1.1 mkdir -p /tmp/pkgs
   scp -O podkop-exp-* luci-app-podkop-exp-* luci-i18n-podkop-exp-ru-* root@192.168.1.1:/tmp/pkgs/
   ```

3. Добавьте `--from /tmp/pkgs` в конец команды установки. Эти файлы установщик не сверяет с
   контрольными суммами GitHub: берите их только со страницы выпуска. Если роутер вообще не видит
   GitHub, скопируйте туда и `install.sh` и запустите
   `sh /tmp/pkgs/install.sh --from /tmp/pkgs`.

## Вернуться на podkop

Удалите пакеты (`luci-i18n-podkop-exp-ru` — только если ставили перевод):

```sh
opkg remove luci-i18n-podkop-exp-ru luci-app-podkop-exp podkop-exp   # OpenWrt 24.10
apk del luci-i18n-podkop-exp-ru luci-app-podkop-exp podkop-exp       # OpenWrt 25.12
```

Верните прежние настройки командой `mv /etc/config/podkop.pre-0.8.8 /etc/config/podkop` (если такого файла нет, удалите
`/etc/config/podkop`; если установщик назвал копию с датой, `/etc/config/podkop.pre-0.8.8-<дата>`,
в ней настройки вашего последнего podkop). Затем поставьте podkop по его README.
